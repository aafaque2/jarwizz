# Migration Notes — Ollama / Llama 3.1 → llama.cpp (Vulkan) + Qwen3-VL-4B

## 1. Summary

The MVP's local model runtime is switched from **Ollama (Llama 3.1/3.2 8B, text-only)** to **llama.cpp with the Vulkan backend serving Qwen3-VL-4B GGUF Q4_K_M (~3–6 GB, Apache 2.0)**. The dev machine's GPU is an **AMD RX 5500M (Navi 14 / gfx1012)** which is **not officially supported by ROCm 7.x** (RDNA3/RDNA4 + Instinct only), so the ROCm path is dropped; Vulkan is cross-vendor and correctly offloads on this hardware without ROCm/CUDA. Qwen3-VL-4B is vision-capable natively, so the runtime now exposes a **single client** (`generatePlan()` + `describeScreen(imageBuffer, prompt)`) for both planning and screen-understanding — no separate text/vision integrations and no multi-model router for v1 (deferred to `08-FUTURE-SCOPE.md`). Browser automation stays DOM-first; vision is scoped to read-screen/desktop/ambiguous cases. A new **Phase 0.5 Hardware & Model Validation** gate must pass before any Phase 1 product code is built.
